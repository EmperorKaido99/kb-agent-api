# TASK-0001: Build .NET Knowledge-Base Agent API (Phase 1 PoC)

## Define
- **Goal**: Implement the .NET API described in `AI_Knowledge_Base_Agent_Roadmap` Phase 1 — a RAG API that answers
  questions grounded in an internal knowledge base, running entirely on local hardware (two laptops each running
  Ollama), before any dedicated-server budget is requested.
- **Constraints**:
  - Free/open-source stack only (no paid licences/APIs).
  - Must work against Ollama's local REST API (default `http://localhost:11434`), for both generation and embeddings.
  - Must support two independent Ollama backends ("two laptops") and route to whichever is available (simple
    load-balancing / pool-of-workers, not distributed inference — that's Phase 2, explicitly out of scope).
  - Must be containerizable with Docker (Docker Compose) for repeatable deployment.
  - External exposure (Cloudflare Tunnel / reverse proxy) is a deployment-time concern, but the API itself must
    support API-key authentication so it's safe to expose.
  - Vector DB: roadmap lists "Qdrant or SQLite + pgvector" — Qdrant chosen for this build (has a first-party .NET
    client, runs as a single Docker container, no extra Postgres dependency for a 2-laptop demo). Documented as an
    assumption for approval below.
- **Definition of Done**:
  - `POST /api/ask` accepts a question, retrieves relevant KB chunks via vector similarity search, sends
    prompt+context to an available Ollama backend, returns a grounded answer.
  - Ingestion path exists to chunk source documents, generate embeddings via Ollama, and load them into Qdrant.
  - Load-balancer picks a healthy/free Ollama backend from configured endpoints (round-robin + basic health check).
  - API-key middleware protects the API.
  - Solution builds; unit tests cover chunking, load-balancer selection, and the ask orchestration (with mocked
    Ollama/Qdrant); `dotnet test` passes.
  - `docker-compose.yml` stands up the API + Qdrant with one command.
  - `memorybank/setup.md`, `memorybank/architecture.md`, `memorybank/features.md`, `memorybank/integrations.md`
    updated to reflect the real stack.

## Deliver
### Implementation Plan
- [ ] `KbAgent.Api` ASP.NET Core 8 Web API project (`src/KbAgent.Api/KbAgent.Api.csproj`)
- [ ] `Configuration/`: strongly-typed options for Ollama backends (list of base URLs), Qdrant connection, chunking
      (chunk size/overlap), API key
- [ ] `Services/OllamaClient.cs` — wraps `/api/generate` and `/api/embeddings` against a given backend URL
- [ ] `Services/OllamaLoadBalancer.cs` — round-robin + lightweight health check (`GET /` or `/api/tags`) across
      configured backends, picks next healthy one
- [ ] `Services/ChunkingService.cs` — splits plain-text documents into overlapping chunks
- [ ] `Services/QdrantVectorStore.cs` — create collection, upsert chunk embeddings + payload (source, text),
      similarity search top-k
- [ ] `Services/RagService.cs` — orchestrates: embed question → vector search → build grounded prompt → call
      load-balanced Ollama → return answer
- [ ] `Endpoints`:
  - `POST /api/ask` — `{ question }` → `{ answer, sources }`
  - `POST /api/ingest` — accepts raw text + source name, chunks/embeds/stores it (simplest path to populate the KB
    for the demo; a CLI/batch tool is out of scope for this pass)
  - `GET /health` — liveness + backend status
- [ ] `Middleware/ApiKeyAuthMiddleware.cs` — validates `X-Api-Key` header against configured key for `/api/*`
- [ ] `appsettings.json` — sample config (2 Ollama backend URLs, Qdrant URL, model names, chunk size, API key
      placeholder)
- [ ] `KbAgent.Api.Tests` — unit tests for `ChunkingService`, `OllamaLoadBalancer` selection logic, `RagService`
      orchestration (mocked `IOllamaClient`/`IVectorStore`)
- [ ] `Dockerfile` (multi-stage build) + `docker-compose.yml` (API + Qdrant services)
- [ ] Update `memorybank/setup.md`, `architecture.md`, `features.md`, `integrations.md`
