# TASK-0002: Multi-format document ingestion (PPTX/DOCX/PDF/XLSX + image OCR) + folder watcher

## Define
- **Goal**: Extend ingestion so the knowledge base can be built from real office documents (PowerPoint, Word,
  PDF, Excel) and images (via OCR), automatically picked up from a configured local folder on a schedule —
  replacing manual `POST /api/ingest` text pastes as the primary way to populate the KB.
- **Constraints**:
  - Free/open-source libraries only (matches roadmap).
  - Must run inside the existing `KbAgent.Api` process — no new services/containers beyond what's already
    planned (in-process `BackgroundService`, per the earlier cron-mechanism discussion).
  - Re-scanning/re-ingesting an unchanged file must not duplicate chunks in Qdrant (documented gap from
    TASK-0001 — being fixed here via delete-by-source-then-upsert).
  - Audio transcription explicitly deferred — user listed PPTX/DOCX/PDF/XLSX as the actual KB content; images
    covered via OCR; audio only if confirmed needed.
  - This sandbox has no access to the user's real laptop filesystem — folder path must be configurable, and
    testing here uses generated/synthetic sample files, not the user's real documents.
- **Definition of Done**:
  - Text extraction implemented for `.pptx`, `.docx`, `.pdf`, `.xlsx`, `.txt`/`.md` (existing), and OCR for
    standalone image files (`.png`/`.jpg`/`.jpeg`/`.bmp`/`.tiff`).
  - A configurable folder path is scanned on a timer (`BackgroundService`); new/changed files are ingested
    automatically; unchanged files are skipped (hash-based state tracking).
  - Re-ingesting a changed file replaces its old chunks rather than duplicating them.
  - `docker-compose.yml` mounts a host folder into the container and installs Tesseract OCR in the image.
  - Unit tests cover what can be verified without native OCR/real user files: extractor factory dispatch,
    Word/Excel extraction (round-tripped via the same libraries used to write them), and change-detection logic.
  - `dotnet build`/`dotnet test` green.
  - memorybank docs updated.

## Discover
### Findings
- Current `POST /api/ingest` (TASK-0001) only accepts raw text in a JSON body — no file parsing at all.
- `RagService.IngestAsync` always creates new random `Guid` chunk IDs, so re-ingesting the same source duplicates
  points in Qdrant — documented as a known gotcha in `memorybank/components/kb-ingest.md`. Fixing this now by
  deleting existing points for a source before upserting new ones (`IVectorStore.DeleteBySourceAsync`, via
  Qdrant's filter-based delete).
- Libraries selected (all free/OSS, NuGet-available):
  - `DocumentFormat.OpenXml` — Word (`.docx`) and PowerPoint (`.pptx`), both OOXML formats it reads directly.
  - `ClosedXML` — Excel (`.xlsx`) cell/sheet text.
  - `UglyToad.PdfPig` — PDF text-layer extraction. Scanned/image-only PDFs (no text layer) are out of scope for
    this pass — would need page-to-image rendering plus OCR, a materially bigger addition; flagged as a known
    limitation rather than silently failing.
  - `Tesseract` (charlesw/tesseract, wraps native Tesseract/Leptonica) — OCR for standalone image files. Needs
    the native Tesseract engine + trained language data; installed via `apt-get install tesseract-ocr` in the
    Dockerfile. Running outside Docker (bare `dotnet run` on the host) requires Tesseract installed separately —
    documented as a limitation.

### Root Cause / Area of Change
New feature (multi-format ingestion) + fixing a documented gap (duplicate chunks on re-ingest) surfaced while
building the automated folder-watcher this task depends on.

### External Research
- DocumentFormat.OpenXml, ClosedXML, PdfPig, Tesseract .NET wrapper — all actively maintained, free/OSS, no paid
  licenses, consistent with roadmap constraint.

### Discovery Summary
Buildable now without the user's real files (tests use generated/synthetic fixtures); folder path and Docker
volume mount are configurable so it works once deployed on the real laptop against the real Documents folder.
